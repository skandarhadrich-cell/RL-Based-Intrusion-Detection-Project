# Prioritized Experience Replay - training report

`data/processed/prioritized_replay_report.md` - generated by `PYTHONPATH=src python -m rl_ids.train_per`

## 1. Setup

- Environment: `IDSEnv2018(split="train")`, 17-feature **real-flow** observations with Gaussian noise and telemetry masking (partial observability). The hidden severity bucket drives transitions/rewards and is never an observation.
- Action mask: the playbook mask (`info["action_mask"]`) is applied at every argmax (acting and bootstrapping); the Q-network sees only the 17 features.
- Algorithm: **Double DQN + PER** - online net selects `a* = argmax_a Q_online(s',a)`, target net evaluates `y = r + γ·Q_target(s',a*)`; transitions are sampled by priority with importance-sampling correction.
- Network: MLP [128, 128] (ReLU), Adam lr=0.001, Huber loss, grad-clip=10.0.
- Replay: **prioritized (proportional)**, capacity 200,000, batch 64, α = 0.6, ε = 1e-05, β 0.4 → 1.0 over 20,000 updates, Warm-up 2,000 transitions, target sync every 1,000 updates.
- Exploration: ε 1 → floor 0.05, ×0.995 per episode (final ε = 0.0500).
- Episodes = 5,000 (exploring starts, uniform over {Normal, Suspicious, Compromised}), steps = 22,147, updates = 20,148.
- Obs pool ≤ 200,000 rows/state; γ = 0.9; seed = 7.

## 2. PER mechanics

- Priority `p_i = |TD_i| + ε`, stored as `p_i^α` in a binary **sum-tree** (O(log N) sampling and priority updates).
- Sampling `P(i) = p_i^α / Σ p_k^α`; new transitions enter at the current **max** priority so nothing starves before its first update.
- Importance-sampling weights `w_i = (N·P(i))^(−β)` (max-normalised) multiply the element-wise Huber loss, un-biasing the prioritized sample.
- Final β = 1.000 (β reaches 1.0 after 20,000 updates, i.e. full correction).
