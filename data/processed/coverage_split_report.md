# Coverage split report

`data/processed/coverage_split_report.md` - generated by `PYTHONPATH=src python -m rl_ids.coverage_split`

Additive corpus carved from the currently held-out days, split so an unseen remainder stays for testing. The original `train.parquet` and `holdout_*.parquet` are untouched.

**Feature scaling.** The `day_*.parquet` files are written *before* preprocessing scales the data, so they hold raw values. Every row here is z-scored with the **train-split scaler** (`scaler.json`, fit on the original train split only) so the coverage corpus matches the scale the models were trained on - no refit.

## Split rule

- PortScan day: **80/20 time cut** at epoch 1499396352 (2017-07-07 02:59 UTC); earlier -> train, later -> test.
- Infiltration: **day vs day** - Wed-28-02-2018 -> train, Thu-01-03-2018 -> test (no within-day leakage).

## Why this split

- PortScan attacks are **clustered late**: only 3,372 of the day's scans sit before the 80% cut, so a 60/40 or 70/30 cut would leave almost none in training. 80/20 is the balance point.
- Infiltration has attack-free gaps mid-day on both days, so whole-day separation is safer than a within-day cut. This mirrors the project's existing day-based holdout philosophy.
