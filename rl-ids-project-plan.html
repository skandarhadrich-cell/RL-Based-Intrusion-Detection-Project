RL-Based Intrusion Detection Agent

Double DQN + Prioritized Experience Replay on CSE-CIC-IDS2018, in a custom Gymnasium environment
7-day plan Environment: Kali VM 3 states · 6 actions γ = 0.90–0.99
Working environment: everything below runs on the Kali VM — no GPU dependency, clean Python/CUDA toolchain, easy bulk dataset handling. Use a dedicated virtualenv so this doesn't collide with the malware-analysis-pipeline environment.

Day 1

Dataset acquisition & preprocessing

Goal: a clean, labeled feature table ready to drive the environment.

Tasks

  • Download the CSE-CIC-IDS2018 CSVs (AWS CICFlowMeter exports) — start with 2–3 representative days (one benign-heavy, one with DoS/Botnet, one with Infiltration) rather than the full 10-day set, to keep iteration fast.
  • Merge CSVs, drop duplicate headers embedded mid-file (a known IDS2018 quirk), coerce dtypes, drop/clip Inf and NaN rows.
  • Reduce the ~80 CICFlowMeter features down to the state features your MDP actually uses: packet rate, byte count, active connection count, TCP flag distribution, destination port status.
  • Map the dataset's attack labels to your 3 MDP states:
    Dataset labelMDP state
    BenignNormal
    Low-confidence anomalies (port scan, early-stage brute force)Suspicious
    Confirmed attacks (DoS, Botnet, Infiltration, Web-Attack)Compromised
  • Keep the attack ground-truth label as a hidden column used only to compute rewards (TP/FP/FN/TN) and for evaluation — never feed it to the agent as an observation (that would leak the answer).
  • Normalize/standardize continuous features; save the cleaned table as Parquet for fast reloading.
Checkpoint: df.isna().sum().sum() == 0, class balance printed, and a 5-row sample manually traced to the correct MDP state.
Day 2

Build the Gymnasium environment

Goal: a working gym.Env that reproduces the state/action structure from your MDP slides.

Tasks

  • Subclass gymnasium.Env. observation_space = Box over the normalized telemetry features (add Gaussian noise / random masking to simulate "partial and noisy telemetry").
  • action_space = Discrete(6): a0 Monitor, a1 DPI, a2 Throttle, a3 Honeypot, a4 Block, a5 Isolate.
  • Enforce A(s) action masking exactly as specified: Normal→{Monitor}, Suspicious→{Monitor, DPI, Throttle, Honeypot}, Compromised→{Monitor, Block, Isolate}. Invalid actions should either be masked at the policy level or heavily penalized.
  • reset() samples a fresh episode start (Normal state, random flow row). step(action) samples the next flow row conditioned on the current state to drive stochastic transitions (attack arrival, escalation, successful mitigation back to Normal).
  • Episode terminates on Isolate (terminal reset per your slide) or after a max step count.
Pitfall: don't hand-wave the transition model — the "state" the agent sees should be an observation of the environment's true underlying condition, which itself evolves based on real flow sequences from the dataset, not just randomly re-sampled rows.
Day 3

Reward function

Goal: R(s,a) = R_detection − C_action(a) − P_latency(a), verified against the worked example.

Reward components

ComponentValues
Detection (R_detection)TN = +1, TP = +18, FP = −12, FN = −40
Action cost (C_action)Monitor 0.0, DPI 1.0, Throttle 1.5, Honeypot 3.0, Block 2.0, Isolate 15.0
Latency penalty (P_latency)α × queue length, applied on DPI/Throttle overuse

Tasks

  • Implement reward as a pure function of (true_label, action) so it's independently testable.
  • Unit-test against the worked episode from the slides at γ = 0.9: 
    t=0 Normal·Monitor    R1=0    → Suspicious
t=1 Suspicious·Throttle R2=-41.5 → Compromised
t=2 Compromised·Block  R3=-2    → Compromised
t=3 Compromised·Block  R4=+18   → Normal (terminal)

Backward returns:
G3 = 18
G2 = -2 + 0.9*18     = 14.2
G1 = -41.5 + 0.9*14.2 = -28.72
G0 = 0.9*(-28.72)     = -25.85
  • If your reward function doesn't reproduce these numbers exactly, fix it before Day 4 — everything downstream depends on this being correct.
Checkpoint: a pytest asserting G0 == -25.85 (±1e-6) for the scripted episode above.
Day 4

Tabular sanity check (Monte Carlo control)

Goal: confirm the environment converges to the known-correct optimal policy before any neural net is involved.

Tasks

  • Implement First-Visit Constant-α GLIE Monte Carlo control directly on the 3-state tabular version of the problem (bucket observations back into {Normal, Suspicious, Compromised}).
  • ε-greedy exploration with ε decaying across episodes (GLIE condition), constant-α update: Q ← Q + α(G − Q).
  • Train for enough episodes to see Q-values stabilize.

Expected result

StateOptimal actionq*
NormalMonitor18.29

CompromisedBlock31.06
Why this step matters: if your tabular agent doesn't converge to this policy, the bug is in your env/reward, not in RL theory. Debugging that here costs minutes; debugging it after Double DQN + PER is wired up costs days.
Day 5

Double DQN

Goal: a stably-training deep agent on the full IDS2018-driven environment, using a plain replay buffer first.

Tasks

  • Q-network: small MLP (e.g. 2–3 hidden layers, 128–256 units) over the normalized telemetry features → Q-values for all 6 actions.
  • Maintain an online network and a target network; sync via hard update every N steps or soft (Polyak) update with τ ≈ 0.005.
  • Double DQN target: use the online network to select argmax_a' Q(s',a'), and the target network to evaluate that action — this decouples selection from evaluation and fixes DQN's overestimation bias.
  • Standard uniform replay buffer (deque or simple ring buffer) to start — get loss curves and reward trending upward before adding complexity.
  • Apply the action mask from Day 2 at both action-selection and target-computation time.
Checkpoint: training reward curve trending upward over episodes, and greedy-policy evaluation starting to favor Monitor/Honeypot/Block in the matching states.
Day 6

Prioritized Experience Replay

Goal: swap in PER without breaking what's already training.

Tasks

  • Implement a sum-tree buffer: priority p_i = |TD-error_i|^α (α ≈ 0.6), sampling probability P(i) = p_i / Σp.
  • Importance-sampling weights: w_i = (N · P(i))^(-β), normalized by max(w), with β annealed from ~0.4 → 1.0 over training to correct the sampling bias as training progresses.
  • After each gradient step, update the priorities of the sampled transitions with their fresh TD-errors.
  • Test the sum-tree in isolation first (insert/sample/update on a toy buffer of 10 items) — leaf-index arithmetic bugs here are the single most common PER bug and are miserable to debug inside a full training loop.
Pitfall: forgetting to multiply the TD-error loss by the IS weight (or forgetting to normalize weights by their max) silently reintroduces the bias PER is meant to correct — the agent will still "train" but converge to a worse policy without any crash to warn you.
Day 7

Train, evaluate, write up

Goal: a trained policy with numbers to back the "Double DQN + PER beats baselines" claim.

Tasks

  • Full training run with ε-greedy decay (e.g. 1.0 → 0.05 over the first 60–70% of episodes).
  • Evaluate the greedy policy on held-out IDS2018 data (a day/attack type not used in training) and report:
    • Detection rate / false-positive rate per state
    • Average episode return
    • Action-usage distribution per state (does it actually learn Monitor/Honeypot/Block?)
  • Compare against the baselines already computed in your slides: passive (always-Monitor), stochastic policy, and the tabular MC optimum — quantify the gap closed by Double DQN+PER.
  • Plot training reward curve, loss curve, and a confusion-style matrix of (true state × action taken).
  • Write up results: MDP formulation recap, architecture, training curves, baseline comparison, limitations (e.g. partial observability, dataset class imbalance).
Deliverables: trained model checkpoint, evaluation script, plots, and a short report tying the numbers back to the MDP theory from your slides.
